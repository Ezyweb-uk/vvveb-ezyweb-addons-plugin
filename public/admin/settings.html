Ezyweb Addons

Plugins list
Orders
Shown under each product name in Sales › Orders › order details. The SKU is read from the product, so a product's current SKU is shown.
Admin products list
1–500. Leave at 0 to keep Vvveb's default of 10.
Show SKU in Products › Products
Products without a SKU show nothing.
The Sku, Model, Barcode, Upc, Ean and Isbn filters in Products › Products find products whose code contains what you type (any case), e.g. 123 finds ABC-1234. Vvveb only finds exact matches.
The Search filter finds products whose name (in any language), SKU or model contains what you type, e.g. dres finds "Summer dress". Vvveb's search only matches whole words in the name and description, and doesn't look at SKUs.
Admin users
Keeps each admin's site access, status and role exactly as set in Admin users: they only change when an admin who can edit other admin users saves them there. Recommended on Vvveb 1.0.9.0 for sites with more than one admin. Admins limited to some sites before this was on may need their sites ticked again.
Editing products and posts
In Vvveb 1.0.9.0, saving a product, post or page created by another admin only saves its name, description, categories and fields. Status, price, stock, SKU and the other main fields stay as they were, even for a Super Admin, while the page still says "saved". With this on, those fields are saved too, for admins whose role has "Edit other users products" or "Edit other users posts". The item keeps its original author. Turn off once core is fixed.
Shop listings
1–100. Leave at 0 to keep the theme's own number. When set, a ?limit= in the page address (1–100) also works, e.g. /shop?limit=48. Home page blocks and related products are not changed.
A category page lists the products in that category and in all of its sub-categories (any depth), each product once, so a parent category with no products of its own no longer shows "No products to display". Sorting, filters and paging still work. Other product blocks on the page are not changed. Replaces the separate Sub-category products plugin: deactivate that plugin when this is on.
SEO
Permanently redirects /en/mypage to /mypage, so each page has one address. Also redirects prefixes that aren't an active language, e.g. /xx/mypage. Other active languages such as /fr/mypage are not changed. Only applies while "Include url slug" is off in Settings › Site.
The theme's <link rel="canonical"> is empty. This fills it with the page's full address, without the query string. If the bundled SEO plugin is active, its canonical address is used instead, and the page still gets exactly one canonical tag.
Stock
Out-of-stock products
When blocking, a product counts as out of stock if its Stock status is ticked below, or if Subtract stock is on and its stock quantity is 0 (a variant's own quantity when one is chosen). Add to cart and Buy now are disabled, listings show "Out of stock", and such products already in a cart are removed on the cart and checkout pages with a message.
Stock statuses that count as out of stock
A disabled product's page already returns 404, but Vvveb still lets it be added to the cart with a direct request, and it stays in carts it was added to before. This blocks the add and removes it from carts on the cart and checkout pages.
Shop front fixes
With the Minify plugin on, the View cart and Checkout buttons in the Add to cart popup link to //cart and //checkout and do nothing. Vvveb's page links also throw a script error on every click. This adds a small script after app.js that fixes both, without changing core files.
Vvveb 1.0.9.0 finds matching products but never shows them on the search page or in the search box's live results, because the theme checks products.count on the product list. This makes that check work, without changing core or theme files. Turn it off once core is fixed.
The search page and the live search boxes find products where every word typed appears anywhere (any case) in the name, description, SKU or model, e.g. 1234 finds SKU ABC-1234 and dres finds "Summer dress". Vvveb only matches whole words of the name and description. On 1.0.9.0, also turn on "Show products in shop search results".
The billing and shipping countries still default to the site address country, but each region shows the theme's placeholder (e.g. "Region") until the customer picks one, instead of the site address region. A region the customer has chosen is kept (from the form or their checkout session). The theme's placeholder option needs selected, e.g. <option value="" disabled selected>Region</option>.
Vvveb requires a region for every checkout address, so customers from a country with no regions (e.g. Jersey, Guernsey, Isle of Man, Gibraltar), or whose regions are all disabled in Settings › Regions, can't place an order. With this on, the Region field is hidden and not required for those countries, and the order is saved with no region (0, as used by tax and shipping zones for "the whole country"). Countries with active regions still require one.
Vvveb lists countries and regions in the order they were added, so later additions and some of the install data are out of order (e.g. County Antrim to County Tyrone and Cumbria come after Wrexham). With this on, the checkout and account address forms list them alphabetically, including the regions loaded when the country changes. Admin lists keep Vvveb's order.
